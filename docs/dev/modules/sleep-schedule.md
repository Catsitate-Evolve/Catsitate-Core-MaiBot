# 睡眠与日程模块

> 源码:`catsitate_core/sleep.py`(睡眠状态机与晚安判定)、`catsitate_core/schedule.py`(日程数据模型/校验/生成/修改)、`plugin.py`(入睡判定 Hook、睡眠拦截、调度 tick、日程生成与恢复、备忘提醒兜底)。

bot 像真人一样有自己的作息:每晚入睡时由 LLM 生成次日日程,白天按窗口活动(可主动发言、刷空间、发说说),到点入睡、自然醒,睡眠期间绝对静默。

## 一、模块职责与生命周期

### 职责

- **日程生成与执行**:入睡时 LLM 依据当日回顾/天气/好感度/到期备忘生成次日作息;失败或首日无日程时用默认作息模板撑场。白天由 `schedule_tick` 按窗口触发主动发言与空间行为。
- **睡眠状态机**:`SleepManager` 维护全局唯一的睡眠状态(awake/sleep + 入睡/醒来时刻),独立持久化 `sleep_state.json`,重启恢复不依赖日程文件。
- **入睡判定**:两条入睡路径——bot 自己说出晚安短句(LLM 判定),或睡眠窗口内安静满 N 分钟(静默入睡)。
- **睡眠绝对静默**:`sleep_gate` 拦截一切入站消息(含命令),入回顾缓冲;醒后生成睡醒回顾。

### 日程数据模型

```json
{
  "date": "YYYY-MM-DD",
  "windows": [
    {"kind": "sleep",    "start": "...T23:00", "end": "...T07:30"},
    {"kind": "daily",    "start": "...T09:00", "end": "...T12:00",
     "activity": "发呆", "plan_speak": false, "topic": "",
     "read_qzone": false, "send_qzone": false},
    {"kind": "greeting", "start": "...T22:00", "end": "...T23:00", "activity": "洗漱准备睡"}
  ]
}
```

- kind 三种:`sleep`(睡眠,恰好 1 个)/ `daily`(日常活动,1~8 个)/ `greeting`(问候陪伴类,窗口起点触发主动问候)。
- 窗口属性:`plan_speak`(是否计划主动发言,随 `topic` 传入触发意图)、`read_qzone`(该窗口刷空间)、`send_qzone`(该窗口发说说)——后两者仅 `daily` 窗口可标。
- 时间精确到分钟(解析容忍 LLM 偶发带秒,落库前统一归一化)。

### 生命周期(一天)

```
醒着(schedule_tick 按窗口触发主动行为/空间行为)
  → 睡眠窗口到达:晚安判定(LLM)或安静满 N 分钟 → 入睡
  → 入睡任务:生成次日日程(LLM,模板兜底)+ 生成发布日记(旁路,睡眠期可执行)
  → 睡眠期:绝对静默(sleep_gate 拦截入站,入回顾缓冲;调度相关 tick 全部让位)
  → wake_at 到点自然醒:睡醒回顾 + 补跑当日结算
```

### 持久化文件

| 文件 | 内容 |
|---|---|
| `schedule.json` | 当日/次日日程 + 修改历史 + 生成标记 |
| `sleep_state.json` | 睡眠状态与入睡/醒来时刻 |
| `sleep_review_buffer.json` | 睡眠期拦截消息缓冲(重启不丢) |
| `remind_fired.json` | 备忘提醒去重标记 |

## 二、完整逻辑

### 1. 日程生成(`ScheduleGenerator.generate`)

入睡时 `_generate_tomorrow_schedule` 调用,目标日 = 明天。prompt = 稳定段(system 模板 `schedule_generate` + bot 人设 + 行为风格,顺序固定保前缀缓存)+ 变量尾(今天回顾、明天天气/节日、重要用户好感度摘要、目标日到期备忘、睡眠时长约束、目标日)。

生成链路(兜底递进):

1. LLM 调用异常 / 返回失败 → 直接返回**默认作息模板**(23:00–07:30 睡、09:00–12:00 发呆、15:00–18:00 随便做点什么、22:00–23:00 洗漱准备睡;睡眠段 end 跨午夜自动 +1 天)+ 显式错误信息(告警「模板兜底」);
2. JSON 解析失败 → 重试,共 `max_regenerate + 1` 次尝试(默认 1+1);
3. `validate_schedule` 校验失败 → 重试;校验内容:恰好 1 个睡眠窗口、活动窗口 1~8 个、时间合法且 end > start、窗口互不重叠、睡眠时长在 `[min_sleep_minutes, max_sleep_minutes]`(默认 240~660 分钟)、kind 合法、`read_qzone`/`send_qzone` 仅 daily 可标;
4. 重试耗尽 → `fix_schedule` 确定性钳制修复:0 个睡眠窗口补插模板睡眠段、2+ 个只留第一个、活动裁到 8、非 daily 窗口的读/发空间标记清除、睡眠时长钳到边界、重叠窗口按开始时间顺延;
5. 修复后仍校验无效或修复本身异常 → 默认模板 + 显式错误。

成功则窗口按时间排序、时间归一化到分钟后落盘。模板兜底日 `_schedule_generated = False`(不视为生成日程),编辑历史清零。

### 2. 入睡

**晚安判定**(`goodnight_check`,挂在 `maisaka.replyer.after_response`,即 bot 自己发出的每条回复):

- 仅在**当前处于睡眠窗口**(可入睡时间)且未入睡时判定,与静默入睡开关无关;
- 规则层过滤 `is_goodnight_utterance`:短句(≤12 字)、无 @、无「」引用、不含「你好/再见」、逗号/顿号仅允许「大家/各位」收尾(「晚安,小明」类称呼他人拒绝)、含睡眠关键词(睡/晚安/安眠/就寝)——只接受 bot 自己的自我入睡表达,防诱导;
- 通过过滤后调旁路 LLM(`sleep_confirm` 模板)判 `SLEEP / NOT_SLEEP / UNSURE`,仅 `SLEEP` 入睡;LLM 失败或解析失败告警后本轮不入睡;
- 空间虚拟流的评论文本不进晚安判定(防深夜短评论触发全局入睡),但任何出站回复(含空间评论)都刷新活动计时,延迟静默入睡。

**静默入睡**(`_sleep_tick`,60s):

- 静默开关关:睡眠窗口起点直接入睡;
- 静默开关开:窗口内安静满 `silent_sleep_minutes`(默认 60 分钟)入睡;安静计时基准 = max(睡眠窗口起点, 最近活动时刻),入站消息与出站回复都刷新活动。

**入睡执行(`_enter_sleep`,幂等)**:

1. 计划醒来时刻 = 日程睡眠窗口的 `end`(无日程/无睡眠窗口时 = 入睡 + 8 小时);
2. 醒来时刻 = `clamp_wake_time`:钳制在 `[入睡+min_sleep_minutes, 入睡+max_sleep_minutes]`(不足顺延醒来、超过提前醒,正常等于计划值);
3. 状态落盘 `sleep_state.json`;标记 `_sleep_window_settled`(该睡眠窗口的入睡任务已执行,见下);
4. 派发入睡任务:生成次日日程 + 生成发布日记(均为旁路 LLM/发布 API,不经消息链,睡眠期可执行)。

**睡眠期绝对静默**(`sleep_gate`,`chat.receive.before_process` BLOCKING EARLY):

- 拦截一切入站消息(含命令),逐条追加进回顾缓冲并落盘,返回 abort;
- 连带效应:好感度计数暂停、日程/空间/提醒相关 tick 全部让位、日终结算与衰减顺延至醒后补跑。

**自然醒**(`_sleep_tick` 检查原始状态而非 `is_sleeping`——否则醒来分支成死代码):当前时刻 ≥ `wake_at` → `wake()` 清状态 → 睡醒回顾(缓冲按流聚合,逐流 LLM 摘要 + 睡眠期到期备忘静态附列,报告写 `sleep_review/reports/*.md`,权限 0600)→ 补跑当日结算(先衰减后结算)。

**睡眠窗口已过而未入睡**(`_maybe_settle_passed_sleep_window`):整夜没睡则不强制入睡,但在窗口结束后补执行入睡任务(次日日程生成 + 日记),以 `_sleep_window_settled` 记窗口 end 每窗口一次。

### 3. 日程窗口执行(`_schedule_tick`,60s)

- 睡眠中跳过;跨午夜时若**旧日程的睡眠窗口仍在进行**(如昨夜 23:00 入睡、现在凌晨 2 点),保留旧日程交给 `_sleep_tick` 处理,不换新模板;正常换日/首日无日程则用默认模板撑场;
- 空白时间(不属于任何窗口)= 自由时间,不触发;
- 每窗口每天只触发一次(`day|start` 标记);全天主动发言计数上限 `daily_speak_limit`(默认 5,每次触发计 1);
- `greeting` 窗口 → 主动问候:仅对「特别」等级持有者,且必须存在其私聊流,否则跳过;
- `daily` 窗口 → 主动发言触发:候选 = 近 24h 活跃流(`batch_counter` 逐流最近 bump)中,说话人好感度 ≥ `speak_threshold_level`(默认「熟悉」)的流(空间虚拟流排除、无当前说话人流跳过);按(等级, 最近活动)降序取前 `speak_max_streams_per_window`(默认 1);经 `maisaka.proactive.trigger` 传入意图——日程活动、`plan_speak` 与 `topic`、全天概览、目标流关系(等级+注记),是否说、怎么说交主程序 LLM 决定。

**窗口属性消费**:

- `plan_speak`/`topic`:进主动发言意图文本;
- `read_qzone`:QQ 空间轮询 tick 在该窗口激活浏览注入泵,日程注入块行末附「(正在刷QQ空间)」;窗口结束收窗并生成空间见闻;
- `send_qzone`:窗口开始即派发发布触发(仅 send 窗口),或 read+send 同窗在首轮拉取收尾派发(刷完想分享);
- 注入块:planner 请求前注入当前窗口活动(已触发则标注「该窗口已过」)、下一窗口预告、当日到期备忘(≤3 条)。

### 4. 日程修改(`update_schedule` 工具)

LLM 可经工具 view / move / add / delete 今日日程:

- view 输出带序号概览,序号是其余操作的定位依据;
- move/add 采用**锚点压缩**:新窗口保持完整,锚点前窗口尾部压缩、锚点后窗口头部压缩(链式)、睡眠窗口与锚点重叠时入睡推迟到锚点结束而醒来不变;任一窗口被挤没(start ≥ end)则整体拒绝并提示,不自动删窗口;
- 活动窗口上限 8,超限返回拟人化拒绝文案;睡眠窗口不可删除;对睡眠窗口的 update 强制 `kind=sleep`(纠正 LLM 误传 daily);
- 所有修改过校验后记入编辑历史(时间/动作/前后快照),与日程一并落盘。

### 5. 备忘提醒兜底(`_remind_fallback_tick`,300s)

当天没有 LLM 生成的日程(模板撑场)时,`remind_at` 到点的备忘由本 tick 直接注入条目归属流(`[备忘提醒] …`);有生成日程则让位(提醒已交日程收录)。成功标记持久化 `remind_fired.json` 跨重启去重,失败不标记留重试;睡眠中不执行;tick 顺带清理跨天日键。详见[备忘录模块](memo.md)。

## 三、限制与回退清单

| 场景 | 行为 |
|---|---|
| 晚安判定 LLM 失败/解析失败/NOT_SLEEP/UNSURE | 本轮不入睡,显式告警;下条回复再判 |
| 晚安短句防诱导 | 规则层硬过滤:超 12 字、带 @/引用、称呼他人一律不进 LLM |
| 日程生成 LLM 异常/失败 | 默认作息模板 + 告警;`_schedule_generated=False`,备忘提醒兜底保持开启 |
| 生成校验失败 | 重生成 `max_regenerate` 次 → 确定性钳制修复 → 仍无效用默认模板并显式报错 |
| 首日/无日程 | 默认模板撑场(不视为生成日程) |
| 醒来时刻 | 钳制 `[入睡+min_sleep_minutes, 入睡+max_sleep_minutes]` |
| 二次入睡 | `_enter_sleep` 以 `is_sleeping` 守卫幂等 |
| 睡眠窗口过而未入睡 | 不入睡,窗口结束后补执行入睡任务(日程+日记),每窗口一次 |
| 跨午夜 | 旧日程睡眠窗口进行中不换新日程;模板睡眠段 end 自动 +1 天 |
| 重启恢复日程 | `schedule.json` 的 date ∈ {今天, 明天} 恢复(夜间重启不丢次日日程);过期但睡眠窗口仍覆盖当前时刻的保留(否则当天无法入睡),否则删除并告警;损坏/结构非法告警后忽略(入睡时重新生成) |
| 重启恢复睡眠 | `sleep_state.json` 独立持久化,未到 `wake_at` 重启后继续睡 |
| 睡眠期 | 入站全拦截入回顾缓冲(重启不丢);主动触发/空间行为/兜底提醒/结算衰减全部让位,醒后补跑 |
| 活动窗口上限 | 8 个,超限拟人化拒绝 |
| 睡眠窗口修改 | 不可删除;update 强制 kind=sleep;时长仍受 min/max 校验 |
| 窗口挤压 | 被挤没(start ≥ end)整体拒绝并提示调整,不自动删窗口 |
| 主动发言节流 | 每窗口每窗触发一次、每窗口最多 `speak_max_streams_per_window` 流、全天 `daily_speak_limit` 次、好感度等级门槛过滤 |
| 门槛配置非法 | `speak_threshold_level` 非法值告警并按默认「熟悉」处理 |
| 日记/日程生成不扰睡眠 | 均走旁路 LLM 与发布 API,不经消息链,睡眠期照常执行 |
