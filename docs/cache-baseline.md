## 命中率归因(请求结构逐段)

主程序 planner 请求 items 结构(system → 插件注入块 → 历史 → 主程序动态块):

| 段 | 稳定性 | 对前缀的影响 |
|---|---|---|
| system | 稳定 | 前缀基座 |
| 插件注入块(规则单条/环境/备忘/好感度) | 等级/注记变化才变;环境 45 分钟;备忘集合驱动 | 已最大化稳定(等级规则由 5 级全量改为单条后进一步缩短) |
| 历史消息 | 追加式增长 | 旧历史全部命中 |
| 主程序动态块(启发式记忆/人物画像/时间/assistant 提醒) | **每轮变化** | 断点之后全部失效 |

58% 命中率 = 「system + 注入 + 历史」前缀占比;断点在主程序每轮变化的动态块(记忆检索结果、时间戳)。该部分插件不可改(约束:不修改主程序)。

## 插件侧缓存纪律落实情况(§4.10)

- [x] 注入块位于 system 之后、历史之前(planner 记录实证,前缀最稳段)
- [x] 注入块按波动分层排序,等级规则按等级单条注入(联调优化,省 token 且缩短块长)
- [x] 旁路 prompt 稳定段前置 + 模板版本化(cache_key = 版本+内容哈希,模板变更即失效)
- [x] 旁路模板接入主程序 prompt 管理,动态数据不进模板文件
- [x] 注入块缓存以内容语义键复用(等级/注记/备忘集合变化才重渲染)
